# Chronica — приватность

Документ описывает **фактическое** поведение приложения: какие сетевые запросы
оно делает и при каких условиях, что именно пишет на диск, какие разрешения
macOS просит и зачем, и как всё это удалить.

Короткая версия: аудио, скриншоты и расшифровки не покидают компьютер.
Телеметрии, аналитики, отправки отчётов о падениях, проверки обновлений и
аккаунтов в Chronica нет — ни включаемых, ни выключаемых.

Смежные документы: [`API.md`](API.md) — локальный HTTP API,
[`DATA.md`](DATA.md) — схема хранилища и CLI,
[`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) — сторонние компоненты.

## 1. Сетевые обращения

Их ровно три, и все три инициирует пользователь.

### 1.1. Hugging Face — скачивание весов моделей

- **Когда:** только по нажатию «Скачать» в разделе «Модели». Служебный
  Silero VAD (1,8 МБ) догружается автоматически вместе с первой ASR-моделью,
  если его ещё нет.
- **Куда:** `https://huggingface.co/<repo>/resolve/main/<файл>` по HTTPS.
  Репозитории: `csukuangfj/sherpa-onnx-nemo-parakeet-tdt-0.6b-v3-int8`
  (Parakeet), `ggerganov/whisper.cpp` (веса Whisper), `csukuangfj/vad`
  (Silero VAD).
- **Что отправляется:** обычный GET (при докачке — заголовок `Range`).
  Ни идентификатора установки, ни учётной записи, ни содержимого ваших данных.
- **Что проверяется:** sha256 файла после загрузки — там, где дайджест известен
  реестру (Parakeet целиком, Silero VAD, `large-v3-turbo` и
  `large-v3-turbo-q5_0`). Для остальных вариантов Whisper дайджест неизвестен, и
  проверяется только размер из `Content-Length`.
- **Ретраи:** до четырёх попыток на файл с экспоненциальной задержкой;
  прерванные файлы докачиваются, уже скачанные пропускаются.

### 1.2. Ollama — описание кадра экрана

- **Когда:** только пока включён «Журнал экрана». По умолчанию он
  **выключен** (`pref.screenEnabled = false`). Частота — раз в минуту по
  умолчанию, на выбор 1 / 2 / 5 / 10 минут.
- **Куда:** `POST <адрес Ollama>/api/generate`. Адрес по умолчанию —
  `http://127.0.0.1:11434`, то есть локальная машина.
- **Что отправляется:** JSON с полями `model`, `prompt`, `images` (массив из
  одного JPEG-кадра экрана в base64), `stream: false` и параметрами генерации.
  Кадр снимается ScreenCaptureKit, уменьшается примерно до 1024 pt по ширине и
  кодируется в JPEG качества 0.6; курсор не захватывается.
  Промпт включает имя активного приложения и заголовок окна.
- **Что НЕ отправляется:** аудио, расшифровки, содержимое баз данных.
- **Таймаут:** 120 с, с явной отменой запроса; при недоступной Ollama
  наблюдение всё равно сохраняется — но только имя приложения и заголовок окна,
  без описания.
- **Проверка доступности** (кнопка «Проверить» в настройках):
  `GET <адрес Ollama>/api/tags` с таймаутом 3 с.
- **Когда запрос не делается вообще:** если кадр не изменился (average hash,
  расхождение меньше 6 бит из 64) и активное приложение с заголовком окна те же;
  если экран заблокирован; если пользователь бездействует дольше периода.

> **Адрес Ollama — свободное текстовое поле, и он не валидируется.**
> По умолчанию это loopback, и тогда данные не покидают компьютер. Если вы
> впишете туда удалённый хост, скриншоты в base64 уйдут на него по обычному
> HTTP — за выбор адреса и за то, что происходит на той стороне, отвечаете вы.

### 1.3. Локальный HTTP API

- **Когда:** только если вы включили его в настройках. По умолчанию сервер не
  поднимается вовсе.
- **Где слушает:** `127.0.0.1:8765` по умолчанию; хост, порт и Bearer-токен
  настраиваются.
- **Правило безопасности, проверяемое при старте:** если хост **не петлевой**
  (`127.0.0.x`, `localhost`, `::1`), а токен пуст, сервер **не стартует** и
  возвращает понятную ошибку. Выставить историю разговоров в сеть без
  авторизации нельзя.
- **Что отдаёт:** ваши же данные — состояние движка, интервалы, транскрипт,
  результаты поиска, бакеты активности, экспорт журнала. Если токен задан, он
  требуется на всех путях, кроме `/api/v1/health` (живость сервера и базы,
  приватного не отдаёт), и сравнивается за постоянное время. Пустой токен
  означает «без авторизации» — это допустимо только на loopback, что и
  проверяется при старте.
- **CORS:** заголовки выдаются только для `Origin` вида
  `http://localhost[:порт]` или `http://127.0.0.1[:порт]`.
- Подробности — [`API.md`](API.md).

### 1.4. Что происходит на этапе сборки (не у пользователя)

Сборка из исходников ходит в сеть: `sherpa-rs` скачивает предсобранные
бинарники sherpa-onnx / ONNX Runtime, `cargo` — зависимости с crates.io. К
работе готового приложения это отношения не имеет.

## 2. Что пишется на диск

Корень данных — `~/Library/Application Support/Chronica/`.

До 0.1.0 продукт назывался Transcriber, и каталог носил прежнее имя. При
первом запуске новой версии старый каталог `.../Transcriber` переносится
целиком (одна операция переименования на том же томе — веса моделей не
копируются), а настройки копируются из прежнего домена
`app.transcriber.mac`. Ничего не удаляется и никуда не отправляется: перенос
локальный, и при его сбое приложение продолжает работать со старым
каталогом, честно показав ошибку. Автозапуск привязан к bundle id, поэтому
прежняя запись остаётся в Системные настройки → Основные → Объекты входа под
именем «Transcriber» — её нужно удалить руками.

### 2.1. `store/transcriber.sqlite` — транскрипция

- `intervals` — границы интервала (ISO-8601 с локальным смещением и
  epoch-мс UTC), длительность, число слов;
- `interval_texts` — **сам распознанный текст**, по строке на канал
  (`mic` / `remote`), число слов, код языка;
- `voice_events` — эпохи голосовой активности: метка времени, канал, дата и
  час. Это «когда была речь», без текста;
- `interval_texts_fts` — индекс FTS5 поверх текстов, для полнотекстового поиска.

Рядом лежат `-wal` и `-shm` (режим WAL). Схема целиком — [`DATA.md`](DATA.md).

**Аудио на диск не пишется.** PCM живёт в кольцевом буфере в памяти
(~10 с на канал), транскрибируется и отбрасывается; файлов записи нет.

### 2.2. `store/screen.sqlite` — журнал дел с экрана

- `activities` — блоки дел: `start_ts`, `end_ts` (epoch-секунды), `app` (имя
  приложения), `title` (заголовок окна), `summary` (описание от vision-модели),
  число наблюдений;
- `observations` — сырые наблюдения: время, приложение, заголовок окна,
  описание, ссылка на блок дела.

**Скриншоты не сохраняются — ни в базу, ни в файлы, ни в кэш.** В схеме нет ни
одной колонки BLOB; кадр существует только в оперативной памяти на время одного
тика (как base64-строка для запроса к Ollama) и освобождается вместе с ним.
Экспорт журнала тоже выгружает только текст.

Ретеншн: по умолчанию записи старше **90 дней** удаляются — при старте
наблюдателя и далее не чаще раза в сутки. Срок настраивается в разделе
«Журнал экрана»: 30 / 90 / 180 дней или «Всегда» (тогда чистка не выполняется).

### 2.3. `store/logs/core.log` — диагностика падений

Пишутся:

- паники Rust (поток, место, сообщение) через panic hook;
- **stderr нативных рантаймов** (ONNX Runtime / sherpa / whisper.cpp) — их
  перехват включён только в собранном приложении и только когда stderr не
  терминал, чтобы dev-запуск не терял консоль;
- маркер начала сессии и редкие предупреждения уровня «warning» из ядра.

**Транскрипты, тексты реплик и описания экрана в лог не пишутся.** Файл
ротируется по достижении 2 МБ (`core.log` → `core.log.1`, архив ровно один).

### 2.4. `Models/`

Скачанные веса ASR и Silero VAD. Ничего пользовательского.

### 2.5. Настройки

Обычные `UserDefaults` приложения (ключи `pref.*`): адрес Ollama, имя
vision-модели, период съёмки, флаги источников, параметры API. Токен API
хранится там же — это не Keychain.

## 3. Разрешения macOS (TCC) и зачем каждое

Диалоги появляются только у подписанного приложения. Тексты объяснений живут в
`apple/Resources/Info.plist`.

| Разрешение | Зачем | Что будет, если не дать |
|---|---|---|
| **Микрофон** (`NSMicrophoneUsageDescription`) | Захват дорожки `mic` через AVAudioEngine | Дорожка микрофона не пишется; системный звук продолжает работать |
| **Запись системного звука** (`NSAudioCaptureUsageDescription`) | Дорожка `remote` через Core Audio process tap на macOS 14.4+ | Системный звук не пишется; приложение честно скажет об этом и продолжит писать микрофон |
| **Запись экрана** (`NSScreenCaptureUsageDescription`) | Две разные вещи: (1) фолбэк захвата системного звука через ScreenCaptureKit, когда process tap недоступен; (2) кадр экрана и заголовок окна для журнала дел | Журнал дел не работает. На 14.4+ системный звук обычно берётся process tap'ом и без этого разрешения обходится |
| `com.apple.security.device.audio-input` (entitlement подписи) | Под Hardened Runtime без него микрофон молча отдаёт тишину | — |

В свежих версиях macOS «Запись экрана» и «Запись системного звука» показаны
одним пунктом «Запись экрана и системного звука» в Системных настройках.

Чего Chronica **не** просит: доступ к Accessibility (имя приложения берётся из
`NSWorkspace`, заголовок окна — из `CGWindowListCopyWindowInfo`, и для последнего
хватает разрешения на запись экрана), к контактам, календарю, файлам,
геолокации, Apple Events и сети как таковой.

App Sandbox выключен (надёжность Core Audio process taps и ScreenCaptureKit),
Hardened Runtime включён. Разбор того, какие послабления Hardened Runtime
сознательно **не** запрошены, — в комментариях
`apple/Resources/Chronica.entitlements`.

## 4. Как удалить все данные

```bash
# 1. Выйти из Chronica (меню в строке меню). Приложение — долгоживущий агент,
#    просто закрыть окно недостаточно.

# 2. Удалить данные: базы, логи и скачанные модели.
rm -rf ~/Library/Application\ Support/Chronica

# 3. Удалить настройки (второй домен — сборки до переименования).
defaults delete io.github.vadim170.chronica
defaults delete app.transcriber.mac

# 4. Удалить само приложение.
rm -rf /Applications/Chronica.app
```

Отдельно отозвать разрешения: Системные настройки → Конфиденциальность и
безопасность → Микрофон / Запись экрана и системного звука.

Точечная чистка без удаления всего: `chronica db retention --days N`
удаляет транскрипцию старше N суток, `chronica db vacuum` сжимает файл
(см. [`DATA.md`](DATA.md)). Журнал экрана чистится сам — по сроку из настроек.

## 5. Чего в Chronica нет

- Нет облака, синхронизации и учётных записей.
- Нет телеметрии, метрик использования и «анонимной статистики».
- Нет отправки отчётов о падениях: `core.log` остаётся у вас на диске.
- Нет автообновления и проверки версий (Sparkle не используется) — обновления
  вы скачиваете сами из GitHub Releases.
- Нет рекламных и аналитических SDK: полный список стороннего кода —
  [`../THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md).
