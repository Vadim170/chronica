# Chronica — локальный HTTP API

Chronica хранит контекст работы **только на устройстве**. Встроенный HTTP-сервер
даёт доступ к этим данным скриптам и внешним инструментам — не выходя за пределы
машины.

Машиночитаемое описание: [`openapi.json`](openapi.json) (оно же отдаётся по
`GET /api/v1/openapi.json`). Схема хранилища и CLI — [`DATA.md`](DATA.md).

---

## Включение

API выключен по умолчанию. Включается в приложении (Настройки → API) — это поля
`ApiConfig` ядра:

| поле      | по умолчанию | что делает                                                   |
|-----------|--------------|--------------------------------------------------------------|
| `enabled` | `false`      | сервер вообще не поднимается, пока не включён                 |
| `host`    | `127.0.0.1`  | адрес прослушивания                                           |
| `port`    | `8765`       | порт                                                          |
| `token`   | `""`         | Bearer-токен; пустой = без авторизации (только для loopback)   |

**Правила безопасности (проверяются при запуске):**

- если `host` **не петлевой** (`127.0.0.x`, `localhost`, `::1`) и `token` пуст —
  сервер **не стартует** и возвращает понятную ошибку. Открывать историю
  разговоров в сеть без токена нельзя;
- токен сравнивается за постоянное время;
- `Authorization: Bearer <token>` обязателен на всех `/api/v1/*`, кроме
  `/api/v1/health` и `/api/v1/openapi.json`;
- запросы обслуживает небольшой пул (3 потока), чтобы один медленный запрос не
  блокировал остальные.

```bash
BASE=http://127.0.0.1:8765
TOKEN=ваш-токен
curl -s "$BASE/api/v1/health"                       # без токена
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/state"
```

## Конверт ответа

Все `/api/v1/*` отвечают в одной форме:

```json
{ "ok": true,  "data": … }
{ "ok": false, "error": { "code": "bad_request", "message": "…" } }
```

Исключение — «файловые» ответы, которые задуманы для сохранения как есть:
`/api/v1/transcript?format=text|md` (текст/Markdown) и `/api/v1/export`
(документ журнала). Ошибки у них всё равно в конверте.

На каждом ответе есть заголовок `X-Chronica-Api-Version: 1`.

### Коды ошибок

| HTTP | `error.code`   | когда                                                        |
|------|----------------|--------------------------------------------------------------|
| 400  | `bad_request`  | плохие/непонятные параметры (время, `limit`, `cursor`, `format`, `bucket`) |
| 401  | `unauthorized` | нет или неверный Bearer-токен                                 |
| 404  | `not_found`    | неизвестный путь или несуществующий `id`                      |
| 405  | `bad_request`  | метод не `GET`                                                |
| 500  | `store_error`  | сбой хранилища (не ошибка ввода)                              |

Разбор времени и параметров **никогда** не даёт 500 — только 400.

### Форматы времени на входе

Параметры `from`/`to` принимают три формы:

1. **ISO-8601 с таймзоной** — `2026-09-03T10:00:00+03:00`
   (в URL `+` кодируется как `%2B`);
2. **`YYYY-MM-DD`** — начало **локальных** суток;
3. **epoch-миллисекунды UTC** — `1788418800000`.

Всё остальное — 400. Сравнение диапазонов идёт по числовому времени, поэтому
смена таймзоны и переход на летнее время ничего не ломают.

## Эндпоинты

### `GET /api/v1/health`

Живость сервера и базы. **Без токена** (как и `/api/v1/openapi.json`),
приватного не отдаёт.

```bash
curl -s "$BASE/api/v1/health"
```
```json
{"ok":true,"data":{"version":"0.1.0","api_version":"1","db_ok":true,
                   "schema_version":3,"fts5":true}}
```

### `GET /api/v1/state`

Снимок движка (`MetricsSnapshot`: состояние, модель, счётчики, CPU/RSS, источники).

Поле `sources[].last_text` — последняя распознанная реплика — по умолчанию
**пустое**; чтобы получить его, добавьте `?include=last_text`.

```bash
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/state?include=last_text"
```

### `GET /api/v1/intervals`

Интервалы транскрипции, **пересекающие** `[from, to]`.

| параметр  | обяз. | по умолчанию | описание                                             |
|-----------|-------|--------------|------------------------------------------------------|
| `from`    | нет   | вся история  | начало периода                                        |
| `to`      | нет   | вся история  | конец периода                                         |
| `channel` | нет   | все          | `mic` / `remote`: оставить интервалы и тексты этого канала |
| `limit`   | нет   | `100`        | 1…1000                                                |
| `cursor`  | нет   | —            | `next_cursor` предыдущей страницы                      |

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/intervals?from=2026-09-03&to=2026-09-04&limit=1"
```
```json
{"ok":true,"data":{
  "count":1,
  "items":[{"id":1,
            "start_at":"2026-09-03T10:00:00+03:00",
            "end_at":"2026-09-03T10:01:00+03:00",
            "duration_s":60.0,
            "channels":[
              {"channel_id":"mic","text":"обсудили релиз Chronica и подписи","words":5,"language":"ru"},
              {"channel_id":"remote","text":"sounds good","words":2,"language":"en"}]}],
  "next_cursor":"1788418800000:1"}}
```

**Пагинация.** `cursor` непрозрачен (сейчас это `start_ms:id`, keyset — страницы
не «съезжают» при новых записях). Передавайте его как есть, пока не придёт
`"next_cursor": null`:

```bash
CURSOR=""
while :; do
  R=$(curl -s -H "Authorization: Bearer $TOKEN" \
        "$BASE/api/v1/intervals?from=2026-09-03&to=2026-09-04&limit=500&cursor=$CURSOR")
  echo "$R" | jq -r '.data.items[].id'
  CURSOR=$(echo "$R" | jq -r '.data.next_cursor // empty')
  [ -z "$CURSOR" ] && break
done
```

### `GET /api/v1/intervals/{id}`

Один интервал целиком. 404 (`not_found`), если такого нет; 400, если `id` не число.

```bash
curl -s -H "Authorization: Bearer $TOKEN" "$BASE/api/v1/intervals/1"
```

### `GET /api/v1/transcript`

«Сшитый» текст за период — то, что удобно скормить редактору или LLM.

| параметр  | по умолчанию | описание                        |
|-----------|--------------|---------------------------------|
| `from`/`to` | вся история | период                          |
| `channel` | все          | фильтр канала                    |
| `format`  | `text`       | `text` \| `md` \| `json`         |

`text` (`text/plain`) — по строке на реплику:

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/transcript?from=2026-09-03&to=2026-09-04"
```
```
[10:00] mic: обсудили релиз Chronica и подписи
[10:00] remote: sounds good
[10:05] mic: дальше делаем нотаризацию
```

`md` — `text/markdown`; `json` — конверт с полями `from`, `to`, `channel`,
`count`, `text`.

### `GET /api/v1/search`

Полнотекстовый поиск по расшифровкам.

| параметр | обяз. | описание                                            |
|----------|-------|-----------------------------------------------------|
| `q`      | да    | слова запроса; соединяются логическим И              |
| `from`/`to` | нет | период                                              |
| `limit`  | нет   | 1…1000, по умолчанию 100                             |
| `cursor` | нет   | `off:N` из `next_cursor`                             |

```bash
curl -s -H "Authorization: Bearer $TOKEN" --get \
  --data-urlencode "q=релиз" "$BASE/api/v1/search"
```
```json
{"ok":true,"data":{"engine":"fts5","count":1,
  "items":[{"id":1,"start_at":"2026-09-03T10:00:00+03:00","end_at":"2026-09-03T10:01:00+03:00",
            "duration_s":60.0,"channels":[…],
            "channel_id":"mic","snippet":"…обсудили «релиз» Chronica и подписи…"}],
  "next_cursor":null}}
```

`engine` — `fts5` (индекс FTS5) или `like` (фолбэк на подстроку, если сборка
SQLite без FTS5). Спецсимволы в `q` безопасны: запрос не может стать
синтаксической ошибкой. Пустой `q` — 400; «ничего не нашлось» — 200 и пустой
`items`. Порядок — новые сверху, один элемент на интервал, поэтому
`limit`/`cursor` считаются в интервалах.

Элемент `items` — обычный `IntervalRecord` (все поля на месте, включая
`channels[].text` целиком) плюс два **аддитивных** поля:

| поле         | описание                                                        |
|--------------|-----------------------------------------------------------------|
| `channel_id` | канал, в тексте которого нашлись слова запроса (если ни в одном — первый непустой) |
| `snippet`    | фрагмент этого текста ≈200 символов вокруг совпадения           |

`snippet` не заменяет `channels[].text`, а избавляет от нужды тащить в UI
целые интервалы по несколько тысяч символов. Совпадения выделены
`«`…`»`, обрыв текста слева/справа помечен `…`; границы фрагмента не режут
слова. Фрагмент считается одинаково при `engine: "fts5"` и `engine: "like"`.

### `GET /api/v1/activity`

Активность речи по бакетам. `from` и `to` **обязательны**. Пустые бакеты внутри
периода заполняются нулями; зона бакетов берётся из `from`.

| параметр | по умолчанию | описание                                  |
|----------|--------------|-------------------------------------------|
| `bucket` | `hour`       | `hour` \| `day`; иначе **400**             |

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/activity?bucket=day&from=2026-09-03&to=2026-09-04"
```
```json
{"ok":true,"data":{"bucket":"day",
  "from":"2026-09-03T00:00:00+03:00","to":"2026-09-04T00:00:00+03:00",
  "buckets":[{"ts":"2026-09-03","counts":[{"channel_id":"mic","count":1},
                                          {"channel_id":"remote","count":1}]}]}}
```

### `GET /api/v1/sessions`

Сессии записи: **факты** «здесь запись включили» и «здесь выключили». По ним
единая лента журнала рисует разделители — не по эвристике «пауза больше N
секунд».

- без `from`/`to` — последние `limit` сессий, **новые сверху** (дешёвый хвост
  истории);
- с границами — сессии, у которых в период попадает **начало или конец**, по
  возрастанию времени, не больше `limit`. Сессия, целиком накрывающая период,
  границ в нём не имеет и не возвращается.

| параметр | по умолчанию | описание                                     |
|----------|--------------|----------------------------------------------|
| `from`   | —            | начало периода (необязательно)               |
| `to`     | —            | конец периода (необязательно)                |
| `limit`  | `100`        | 1…1000; иначе **400**                        |

`stop_reason`: `user` — остановил пользователь, `error` — авария (паника DSP,
потеря ASR-воркера, watchdog зависшего DSP, прерванная по дедлайну остановка).
**Пустые `ended_at` и `stop_reason`** означают, что сессию никто не закрыл:
процесс убили — это и есть «здесь приложение закрылось». У идущей прямо сейчас
записи сессия тоже пустая — она ещё не закончилась.

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/sessions?from=2026-09-03&to=2026-09-04"
```
```json
{"ok":true,"data":{"count":2,"items":[
  {"id":41,"started_at":"2026-09-03T10:00:00+03:00",
   "ended_at":"2026-09-03T10:42:30+03:00","stop_reason":"user"},
  {"id":42,"started_at":"2026-09-03T12:00:00+03:00",
   "ended_at":"","stop_reason":""}]}}
```

### `GET /api/v1/export`

Документ журнала за период — **та же форма, что у экспорта в приложении**
(`JournalExport`), поэтому файл взаимозаменяем. `from` и `to` обязательны,
`format` — `json` (по умолчанию) или `md`.

Ответ — сам документ, **без конверта**: его можно сразу сохранить в файл.
Экранные «дела» знает только приложение, поэтому из API `activities` приходит
пустым, а транскрипция заполнена.

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
  "$BASE/api/v1/export?from=2026-09-03&to=2026-09-04" > journal.json
```
```json
{"product":"Chronica",
 "exportedAt":"2026-09-03T12:00:00+03:00",
 "from":"2026-09-03T00:00:00+03:00",
 "to":"2026-09-04T00:00:00+03:00",
 "activities":[],
 "transcription":{"count":2,"intervals":[
   {"id":1,"startAt":"2026-09-03T10:00:00+03:00","endAt":"2026-09-03T10:01:00+03:00",
    "durationS":60.0,
    "channels":[{"channelId":"mic","text":"обсудили релиз Chronica и подписи",
                 "words":5,"language":"ru"}]}]}}
```

Ключи документа — camelCase (как у приложения), в отличие от snake_case
остального API. Это осознанно: форма файла экспорта фиксирована.

### `GET /api/v1/openapi.json`

Отдаёт [`docs/openapi.json`](openapi.json). Без токена.

## CORS

Заголовки CORS выдаются **только** если `Origin` — локальная страница:
`http://localhost[:порт]` или `http://127.0.0.1[:порт]`. Тогда сервер эхом
возвращает этот Origin в `Access-Control-Allow-Origin` и добавляет
`Access-Control-Allow-Headers: Authorization, Content-Type`,
`Access-Control-Allow-Methods: GET, OPTIONS`. Любой другой Origin (в т.ч. `https://localhost`)
CORS-заголовков не получает. `OPTIONS` отвечает `204` и обрабатывается до
авторизации — браузер не шлёт `Authorization` в preflight.

## Совместимость

**v1 стабилен.** Он расширяется **только аддитивно**: могут появляться новые
эндпоинты, новые параметры и новые поля в `data`. Существующие поля не
переименовываются, не меняют тип и не исчезают. Ломающие изменения, если
когда-нибудь понадобятся, приедут как `/api/v2/*`.

Клиентам стоит игнорировать незнакомые поля и не полагаться на порядок ключей
в JSON.

### Исторические пути (вечные алиасы)

Существовали до v1 и сохраняются как есть — форма ответа **не** меняется и
конверта `data` у них нет:

| путь                     | ответ                                        |
|--------------------------|----------------------------------------------|
| `GET /api/intervals`     | `{ ok, count, intervals: [...] }`             |
| `GET /api/transcriptions`| алиас `/api/intervals`                        |
| `GET /api/voice-activity`| `{ ok, buckets: [...] }`, `type=hourly\|daily`|
| `GET /api/state`         | `{ ok, state: {...} }`                        |

`from`/`to` здесь обязательны и принимают только ISO-8601. Ошибки — в старой
форме `{ "ok": false, "error": "текст" }`. Для нового кода используйте `/api/v1/*`.
