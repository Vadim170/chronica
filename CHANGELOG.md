## [0.1.0] — 2026-09

Первый публичный релиз: подписанный и нотаризованный DMG для macOS.

### Added

- **Chronica**: проект переклассифицирован из транскрибатора в локальный сборщик
  контекста работы; продуктовое переименование Transcriber → Chronica доведено
  до всего, что видит пользователь:
  - bundle id `app.transcriber.mac` → **`io.github.vadim170.chronica`**;
  - исполняемый файл и продукт SwiftPM → **`Chronica`**
    (`Contents/MacOS/Chronica`, `swift run Chronica`);
  - папка данных `~/Library/Application Support/Transcriber` →
    **`.../Chronica`**, с одноразовой миграцией при запуске: старый каталог
    переносится целиком (переименование на том же томе — 640 МБ весов моделей
    не копируются), а при сбое переноса приложение продолжает работать со
    старой папкой и показывает ошибку, ничего не удаляя;
  - настройки: значения `pref.*` однократно копируются из домена старого
    bundle id, если в новом их ещё нет;
  - автозапуск: `SMAppService` привязан к bundle id, поэтому при первом
    запуске регистрация восстанавливается под новым id — старую запись
    «Transcriber» в Объектах входа нужно удалить руками;
  - разрешения macOS (микрофон, запись экрана) после смены bundle id выдаются
    заново — для обновляющихся с dev-сборки это разовое действие;
  - CLI ядра переименован в **`chronica`**.
  Внутренние имена намеренно не менялись: крейт `transcriber-core`, FFI
  `transcriber_core`/`TranscriberCore`, файл базы `transcriber.sqlite`.
- **Интерфейс локализован: английский и русский, следует языку системы.**
  Все пользовательские строки (включая ошибки, подсказки, промпт vision-модели
  журнала экрана и строки Info.plist для системных запросов доступа) живут в
  String Catalog со стабильными семантическими ключами; формы слов у чисел
  («1 запись» / «2 записи» / «5 записей») — через плюрализацию, даты и числа —
  по региональным настройкам пользователя. Другой язык для одного приложения
  выбирается в Системных настройках → Основные → Язык и регион → Приложения.
- **Окно «О Chronica»** вместо модального алерта: иконка приложения, версия и
  номер сборки, авторство, ссылка на репозиторий, «работает полностью на этом
  компьютере», лицензия MIT, кнопка «Сторонние компоненты» (открывает
  `THIRD_PARTY_NOTICES.md` из бандла, а без бандла — страницу на GitHub) и
  обязательная атрибуция модели Parakeet TDT (© NVIDIA, CC-BY-4.0).
- **Журнал дел с экрана (только macOS)**: периодический скриншот (ScreenCaptureKit)
  → локальная маленькая vision-LLM (Ollama) → описание выполняемой работы.
  Наблюдения сессионизируются в блоки «дел» (одно приложение/контекст = один блок
  со start/end), неизменные кадры отсеиваются perceptual-hash без вызова LLM.
  Хранение — отдельная SQLite (`screen.sqlite`, epoch-время); скриншоты не
  сохраняются. Выключено по умолчанию.
- **Раздел «Журнал» — единая лента по времени**: дела с экрана и реплики
  транскрипции идут одним списком вперемешку (новое сверху), без переключателя
  «Дела / Транскрипция». Границы сессий отмечены тонкими линиями — «запись
  включена», «запись остановлена», «приложение закрылось» (сессия не закрыта
  штатно) и «сбой записи»; на стыке суток остаётся заголовок дня. Общий выбор
  периода (от-до / «Сегодня»), поиск по репликам (включая семантический) и по
  описаниям дел, график голосовой активности и экспорт за период — сквозные.
- **Панель меню-бара показывает историю, а не только текущую сессию**: лента
  строилась из событий в памяти, поэтому после перезапуска приложения старые
  транскрипции в ней исчезали. Теперь при показе панели подтягивается хвост
  истории из хранилища, поверх которого ложатся живые реплики текущей сессии,
  с теми же разделителями сессий, что и в окне.
- **Экспорт журнала за период** (JSON / Markdown): единый структурированный
  документ — дела + открытые окна (наблюдения экрана во времени) + транскрипция
  **поканально** (та же форма, что отдаёт HTTP API: интервалы → каналы
  {channelId, text, words, language}).
- **Локальный HTTP API v1** с машиночитаемым описанием OpenAPI
  (`GET /api/v1/openapi.json`, он же `docs/openapi.json`): состояние движка,
  интервалы с keyset-пагинацией, «сшитый» транскрипт (`text`/`md`/`json`),
  полнотекстовый поиск, бакеты голосовой активности, экспорт журнала. Единый
  конверт ответа, коды ошибок, Bearer-токен со сравнением за постоянное время,
  CORS только для локальных страниц. Старые пути `/api/*` сохранены как вечные
  алиасы. Документация — `docs/API.md`.
- **CLI `chronica`**: `today`, `transcript`, `search`, `stats`, `export`,
  `sessions`, `db` (`info`/`vacuum`/`retention`) и `transcribe` для разовой
  проверки ASR.
  Читает ту же базу и не требует запущенного приложения. Документация —
  `docs/DATA.md`.
- **Журнал сессий записи** (схема базы v3, таблица `sessions`): ядро
  запоминает, когда запись включили и когда выключили — по факту, а не по
  эвристике «пауза больше N секунд». Незакрытая сессия означает «приложение
  закрылось, не остановив запись», аварийная — паника или зависание движка.
  По этим фактам единая лента журнала рисует разделители. Доступно из
  приложения, `GET /api/v1/sessions` и команды `chronica sessions`
  («начало · конец · причина · длительность»), счётчик — в `chronica db info`.
- **Полнотекстовый поиск (FTS5)** по расшифровкам — в приложении, API и CLI,
  с автоматическим откатом на поиск по подстроке, если сборка SQLite без FTS5.
- **Silero VAD реально включён**: веса берутся из каталога моделей и догружаются
  вместе с любой ASR-моделью. Раньше их не ставил никто, поэтому в релизе всегда
  работал простой RMS-детектор, а слайдер «порог речи» ничего не менял. Если
  весов нет — честное предупреждение и явный откат на RMS.
- **Проверка sha256 скачанных моделей** там, где дайджест известен реестру;
  повторные попытки с экспоненциальной задержкой, докачка прерванных файлов
  через HTTP `Range`, пропуск уже скачанных.
- **Дистрибуция**: entitlements для Hardened Runtime, подпись Developer ID
  «изнутри наружу», нотаризация, DMG с томом и симлинком на `/Applications`,
  сгенерированная кодом иконка приложения. Скрипты `package-app.sh`,
  `sign-notarize.sh`, `make-dmg.sh`, `make-icon.sh` и релизный workflow по тегу.
- **Onboarding в панели меню-бара**: пока активная модель не скачана, вместо
  тупика показывается ровно одно понятное действие — кнопка «Скачать модель
  Parakeet» с размером и прогрессом загрузки; при запрете доступа к микрофону —
  кнопка перехода в нужный раздел Системных настроек.
- **Настройка срока хранения расшифровок** (30 / 90 / 180 / 365 дней или
  «Всегда»): записи старше выбранного срока ядро удаляет автоматически.
- **Окно «Диагностика»** (Настройки → Дополнительно): технические показатели
  движка — загрузка, скорость, очередь, память — вынесены из повседневного
  интерфейса в отдельное небольшое окно.
- **Мягкое завершение**: приложение дожидается остановки ядра и записи хвоста
  перед выходом, вместо обрыва текущего интервала.
- **Сон и пробуждение**: захват корректно приостанавливается на засыпании и
  восстанавливается после пробуждения, с честным статусом в интерфейсе.
- CI (GitHub Actions): rustfmt/clippy/тесты ядра на Ubuntu и macOS, `cargo check`
  полного набора фич реального ASR, сборка и тесты macOS-приложения против
  mock-ядра, линт релизной обвязки и проверка синхронности версий.
- Пайплайн: сбои ASR по чанкам видны в UI событием ошибки (раньше — молчаливая
  потеря текста); ASR-воркер переживает Rust-панику бэкенда (интервал
  дропается с событием ошибки, воркер продолжает работу).
- Crash-диагностика: паники и stderr C++-рантайма пишутся в `logs/core.log`
  (с ротацией на 2 МБ). Транскрипты в лог не попадают.
- Сборка без ML-рантаймов: `TRANSCRIBER_CORE_MOCK=1` + `FEATURES=store,api,download,mock-asr,ffi`
  собирает приложение против mock-ядра (для CI и разработки без cmake/ORT).
- Публичная документация: `README.md` (EN) и `README.ru.md`, `docs/PRIVACY.md`,
  `docs/BUILD.md`, `docs/API.md`, `docs/DATA.md`, `CONTRIBUTING.md`,
  `SECURITY.md`, `THIRD_PARTY_NOTICES.md`.

### Changed

- **Главное окно сведено к трём разделам**: Журнал · Модели · Настройки.
  Разделы «Live» и «Дашборд» убраны — живая лента живёт в панели меню-бара.
- **Настройки сведены к трём секциям**: Основные · Журнал экрана ·
  Дополнительно. Всё, что нужно ежедневно, лежит сверху; нарезка интервалов,
  VAD, адрес Ollama, локальный API и диагностика убраны под «Дополнительно».
  Частота наблюдения экрана и срок хранения журнала стали понятными списками
  (1/2/5/10 минут; 30/90/180 дней или «Всегда») вместо слайдера в секундах.
- **Инженерные показатели убраны из повседневного интерфейса**: CPU, RAM, RTF,
  лаг, очередь и потери больше не показываются ни в панели меню-бара, ни в
  главном окне. Раздел «Дашборд» убран, а все эти показатели собраны в
  отдельном окне «Диагностика» (Настройки → Дополнительно).
- Vision-модель по умолчанию — `qwen3-vl:2b`: прежний дефолт распространялся под
  некоммерческой лицензией. Имя модели и адрес Ollama остаются настройками.
- Буфер аудио увеличен до ~10 с на канал: кольцо обязано быть глубже сторожевого
  таймера DSP, иначе сэмплы терялись молча ещё до сигнала о зависании.
- Схема базы поднята до v2 с пошаговой миграцией: диапазоны времени считаются по
  epoch-миллисекундам, а не лексикографическим сравнением ISO-строк (оно врало
  при смене таймзоны и переходе на летнее время). База новее кода не открывается.
- Провайдер ASR по умолчанию: CPU (CoreML дублировал модель в RAM и тёк
  autoreleased-объектами на фоновом потоке).
- Ошибки загрузки модели и store-запросов больше не глотаются в macOS-приложении.

### Fixed

- **Потеря хвоста записи при остановке**: при штатной остановке DSP сбрасывает
  хвост текущего интервала, а ASR дорабатывает всю очередь — раньше последние
  секунды не доезжали до хранилища.
- **Дрейф таймлайна интервалов** примерно на секунду на каждый рез по тишине:
  границы интервалов накапливали расхождение со стенными часами.
- **Прогресс скачивания модели не доходил до UI в простое**: события
  `.modelProgress` приходят вне сессии записи, а общий guard по поколению молча
  их отбрасывал — пользователь видел «зависший» прогресс.
- **Честные тексты запросов разрешений**: строки TCC объясняют, зачем именно
  нужен доступ к записи экрана (захват системного звука и, отдельно,
  необязательный журнал дел), вместо обобщённой формулировки.
- Повторный запрос разрешения на запись экрана на каждом тике наблюдателя.
- **CLI `chronica` падал сразу после сборки приложения**: сборка ядра для
  macOS-оболочки пересобирала заодно и бинарь CLI с ML-фичами, и он получал
  динамические зависимости на ONNX Runtime / sherpa без rpath
  («Library not loaded … no LC_RPATH's found»). Теперь для приложения
  собирается только библиотека, а CLI собирается своей командой без
  ML-рантайма — бинарь самодостаточен. Команда `transcribe` (проверка ASR на
  WAV) в такой сборке недоступна и подсказывает, как собрать вариант с ML.
- **Паника CLI при обрыве конвейера**: `chronica today | head` заканчивался
  «failed printing to stdout: Broken pipe» вместо тихого выхода. Теперь при
  закрытом читателем stdout CLI завершается молча с кодом 0 (как `cat`,
  `grep`, `git log`), а прочие ошибки записи, как и раньше, попадают в stderr
  с ненулевым кодом.

## [0.0.1] — 2026-06-19

Первая рабочая версия (не публиковалась).

- Rust-ядро `transcriber-core`: двухканальный пайплайн (микрофон + системный
  звук), VAD, нарезка на интервалы по тишине, ASR
  (Parakeet TDT v3 int8 через sherpa-onnx; Whisper через whisper.cpp),
  SQLite-хранилище, live-метрики, HTTP API, менеджер моделей (34 модели, HF).
- macOS menu-bar приложение (SwiftUI): popover со статусом и Live-лентой,
  окно с разделами Live/История/Дашборд/Модели/Настройки, семантический поиск
  по истории, горячее применение настроек, метрики CPU/RAM.
- Android-клиент (Kotlin/Compose) на том же ядре через UniFFI.
